# 平台解析链路说明（逆向与维护指南）

> 本文档记录各平台"分享链接 → 原始资源"的解析链路。
> 均为公开网页可观察到的行为整理；**字段会随版本变动**，失效时按下述方法重新抓包验证。

## 抓包验证方法（标准流程）

1. 手机安装 mitmproxy / Charles，配置代理并信任证书（iOS 需额外开启完全信任）。
2. 微信/QQ 中打开分享链接 → 用 Safari 打开，观察请求链：
   - 短链 30x 跳转（记录 Location 链）
   - 详情页 HTML（记录内嵌 JSON 的变量名与结构）
   - 媒体 CDN 请求（记录是否带水印参数、Referer 校验）
3. 对比 App 内分享的 H5 预览页，确认字段命名。
4. 更新对应 parser 的字段路径，跑通一条真实链接后提交。

## 1. 抖音（2026-11 大改版后实测）

```
分享文案 → v.douyin.com/{code}   ⚠️ 分享码可能含前导连字符（如 -FkW8ZGM_XU），
  └─30x→ iesdouyin.com/share/{video|note}/{id}     必须原样携带，缺连字符会 302 到首页

数据源 A（主路径，纯 HTTP 不依赖 WebView）：ttwid + 分享页 SSR
1. POST ttwid.bytedance.com/ttwid/union/register/
   body: {"region":"cn","aid":1768,"needFid":false,"service":"www.ixigua.com",
          "migrate_info":{"ticket":"","source":"node"},"cbUrlProtocol":"https","union":true}
   └─ JSON data.redirect_url（ixigua 回调页，2026-11 起不再直接发 ttwid Cookie）
2. GET redirect_url → 响应 Set-Cookie 里取 ttwid=...
3. GET iesdouyin.com/share/{video|note}/{id}/  （Cookie: ttwid=...）
   └─ HTML 内嵌 window._ROUTER_DATA
      loaderData["video_(id)/page"|"note_(id)/page"].videoInfoRes.item_list[0]
        ├─ desc / author.nickname
        ├─ video.play_addr.url_list  → playwm 带水印地址；playwm→play 替换仍有效（实测 8.8MB→6.9MB）
        └─ images[].url_list / live_photo + live_image.url_list → 图集与实况
   ⚠️ 无 ttwid 时同页 SSR 只有 itemId，videoInfoRes 为空 —— ttwid 是本路线命门

数据源 B（兜底）：WebView 捕获（DouyinCaptureView 离屏挂根部）
  让抖音 H5 在真浏览器环境自己跑起来（前端天然带签名），注入 JS 钩子截获：
  1) XHR/fetch 按【响应内容特征】匹配（aweme_detail/item_list/videoInfoRes）
  2) 轮询 window._ROUTER_DATA（SSR 内嵌数据）
  3) <video> currentSrc/src 及 <video><source src> 播放直链（单清晰度）
  4) note 图文页 DOM <img> 图集（byteimg/zjcdn/douyinpic 特征）
```

- 已废弃：feed/detail API 需要 a_bogus 签名；纯 SSR（无 Cookie）已客户端渲染化。
- ratio 参数（540p/720p/1080p）可在 play 直链上替换尝试更高档，但部分源只有低档。
- 实况视频是普通 MOV，直接 `.pairedVideo` 合成 Live Photo 可能被 iOS 拒绝，
  代码已做降级（分开保存）。强制合成的进阶方案：用 AVFoundation 给 MOV 注入
  Apple 实况元数据（`com.apple.quicktime.content.identifier` + `StillImageTime` 轨道）。

## 2. 小红书

```
分享 → xhslink.com/{code}
  └─30x→ xiaohongshu.com/explore/{noteId}?xsec_token=...&xsec_source=...
GET 该页（保留全部 query！token 缺失会 403/风控）
  └─ window.__INITIAL_STATE__ = {...}（含字面量 undefined，需替换为 null）
     noteDetailMap[noteId].note
       ├─ imageList[].urlDefault|url      → 原图（CDN 本身无水印）
       ├─ imageList[].livePhoto:"true"
       ├─ imageList[].livePhotoUrl        → 实况配对视频
       └─ media.video.media.stream.h264[] → 各清晰度档位，每项 masterUrl + avg_bitrate，
            按编码优先级（h264→h265→av1→vkey）取该格式下 avg_bitrate 最高 = 最高分辨率
```

- **免 Cookie 结论（开源项目验证）**：note 页 `__INITIAL_STATE__` 是服务端渲染，
  匿名请求任何 IP 都可读（tamnd/xiaohongshu-cli、XHS-Downloader 均如此实现）；
  只有签名 API（edith 域，需 x-s/x-s-common 签名）才要登录 Cookie —— 本项目不使用。
- **2026-11 改版适配（真实链接复现实测）**：
  1. noteDetailMap 消失 → 新结构 `noteData.data.noteData`（双路径兼容已实现）
  2. `imageList[].urlDefault` 可能为空串 → 依次回退 url → urlPre
  3. 用户昵称字段 nickname → nickName（两者兼容）
  4. 视频字段 `note.video.media.stream` 与 `note.media.video.media.stream` 双挂载兼容
- ⚠️ livePhotoUrl 实况视频轨平台自带水印，无法去除（XHS-Downloader 同样标注"含水印"）。
- 支持链接：explore/{id}、discovery/item/{id}、user/profile/{uid}/{id}、xhslink 短链。

## 3. 微博（免登录访客方案，已验证）

```
分享 → weibo.com/{uid}/{bid} | m.weibo.cn/status/{bid}
GET m.weibo.cn/statuses/show?id={bid}
  └─ JSON { ok:1, data:{...} }
       ├─ pics[].large.url > original.url > url → 原始尺寸图（http→https）
       ├─ pics[].type=="livephoto" + pics[].videoSrc → 实况配对视频
       │    ⚠️ videoSrc 是 video.weibo.com 包装地址；
       │    内部 livephoto.us.sinaimg.cn/*.mov 直链 403，不能用
       ├─ pic_ids[] 兜底 → https://wx1.sinaimg.cn/large/{pid}.jpg
       └─ page_info.media_info
            mp4_1080p_mp4 > mp4_720p_mp4 > mp4_ld_mp4 > stream_url → 取最高可用清晰度
```

- **免登录原理**：show 接口对移动端 iOS Safari UA 宽松，多数情况无 Cookie 可用；
  被拒时走访客系统自动换取访客 Cookie（非用户登录）：
  1. POST passport.weibo.com/visitor/genvisitor（fp=设备指纹）→ JSONP 取 tid
  2. GET passport.weibo.com/visitor/visitor?a=incarnate&t={tid}&w=3&c=100&cb=cross_domain
  3. Set-Cookie 得 SUB/SUBP，带在后续 show 请求上
- 必需 Headers：iOS Safari UA + `Referer: https://m.weibo.cn/` +
  `X-Requested-With: XMLHttpRequest` + `MWeibo-Pwa: 1`（PC UA 会 403/返回访客页）。
- 图片域 sinaimg.cn 校验 Referer，下载时带 `Referer: https://weibo.com/`（已实现）。
- **无水印图床档位（本机 curl 实测，同 pid 改档位前缀）**：
  `woriginal`（原尺寸无水印）> `orj1080` > `osj1080`/`oslarge`(690)。
  常规档 `mw690`/`mw2000`/`large` 均带水印（large 即 mw2000）。
  代码按候选链 woriginal→orj1080→osj1080→原地址 逐档尝试，404 自动回退。
- **烧像素型水印**：博主开启"图片水印"后，水印在微博上传时就烧进了所有档位
  （含 woriginal 原图，同尺寸不同字节可证实）——任何 URL/接口都拿不到干净版。
  此时走 App 内自动去水印（AppDelegate.swift 零依赖 inpainting：底部区域
  多遍递进阈值检测 → 连通域过滤 → 膨胀 → 洋葱剥皮填充 + 扩散平滑，GIF 与
  过小/过大命中区域自动跳过）。
- **2026-11-06 风控复现（本机实测，视频修复版校准）**：
  1. PC ajax statuses/show 对访客 Cookie 只返回空壳（ok=1 但无 playback_list）
     —— 多清晰度档位失效，1080p 免登录拿不到，720p 无水印已够用
  2. m.show 免登录仍稳：视频帖 media_info 只剩 stream_url/stream_url_hd
     （720p mp4 无水印），旧 mp4_1080p_mp4 等键消失；page_info['urls'] 有
     mp4_720p_mp4/mp4_ld_mp4 兜底
  3. 视频 CDN（f.video.weibocdn.com）裸请求 403，必须带 Referer: weibo.com
     （下载器阶梯已把 Referer 组提前）
  4. 部分帖子 stream_url 是 http://（iOS ATS 拦截）→ 代码强制 https 化 +
     Info.plist NSAppTransportSecurity 豁免兜底
  5. feed/搜索类接口风控（432/-100），单帖 show 接口稳；show 失败时
     UA/访客 Cookie 三组轮换重试

## 4. X（推特）

```
分享 → x.com/{user}/status/{id}（或 t.co 短链 30x 展开）
数据源（按优先级，均无需登录）：
A. GET cdn.syndication.twimg.com/tweet-result?id={id}&token=x&lang=zh-cn
   └─ mediaDetails[]:
        type=photo        → media_url_https + ?format=jpg&name=orig（原始分辨率）
        type=video        → video_info.variants 中 mp4 里 bitrate 最高（原画质）
        type=animated_gif → 同上选 mp4；media_url_https 为 tweet_video_thumb 缩略图
B. GET api.fxtwitter.com/status/{id}（兜底）
   └─ tweet.media.all[]: type photo/gif/video，url 即直链
```

- **原图关键点**：twimg 不带 `name=orig` 参数返回的是 ~680px 缩略版；
  `?format=jpg&name=orig` 才是原始分辨率（png 格式用 `format=png`）。
- **推特 GIF 就是循环 MP4**（video.twimg.com），无原生 Live Photo 概念。
  保存为系统实况的完整管线在 iOS 原生层：抽首帧 → AVAssetWriter 重封装为 MOV
  并注入 `com.apple.quicktime.content.identifier`（UUID）+ StillImageTime 元数据轨道
  （SInt8 值 0 @ 0s）→ `.photo` + `.pairedVideo` 提交。
- syndication 的 `token=x` 若失效（invalid token），切换 fxtwitter 即可；两者字段互备。
- twitter.com、x.com、t.co、fixupx/fxtwitter 镜像链接均已识别。

## 5. 闲鱼（受限）

```
分享 → h5.m.goofish.com/item?id=... （或淘口令/2taobao.net 中转）
详情数据走 mtop 签名接口：sign = md5(token + '&' + t + '&' + appKey + '&' + data)
  token 来自 _m_h5_tk Cookie，appKey 轮换 → 纯 HTTP 方案维护成本高
```

- 当前实现：分享页 og:image + 页面内嵌 JSON 中的 img.alicdn.com 地址，
  去除 `_400x400` 缩放后缀取原图。
- **完整方案（P2）**：App 内嵌 WebView 加载商品页 → 注册 resource load 拦截
  （WKURLSchemeHandler / should Intercept）→ 收集视频与多图 → 用户点选保存。
  注意 WebView 方案在 iOS 上无法拦截 App 内（非 WebView）流量，只能覆盖 H5 页。

## Live Photo 技术要点

- iOS 实况 = `PHAssetCreationRequest` + `.photo`(HEIC/JPEG) + `.pairedVideo`(MOV) 两个资源。
- `.pairedVideo` 系统会校验 MOV 内的 Apple 实况元数据；不合法则整个保存事务失败。
- 代码策略（三级回退，全部在 `LivePhotoSaverPlugin.swift`）：
  1. 直接按 `.photo` + `.pairedVideo` 提交（上游本就是合法实况资源时一步到位）
  2. 失败 → AVAssetReader/Writer 重封装 MOV 并注入实况元数据（含 GIF 抽首帧）后重试
     —— 推特 GIF、抖音/小红书实况视频走这条路径
  3. 仍失败 → 图片+视频分开保存，返回 `'separate'` 由 UI 提示
- 若上游平台开始提供标准实况导出，第 1 步即可命中，无需转换。

## 同类小程序逆向结论（"一键解析" / "解析去水印助手"）

用户参照的两个微信小程序均已解包（微信 4.0 wxapkg：`%APPDATA%/Tencent/xwechat/radium/users/<hash>/applet/packages/wx{appid}/{ver}/__APP__.wxapkg`，
格式 `V1MMWX` + PBKDF2-HMAC-SHA1(小程序appid, salt="saltiest", 1000轮) → AES-256-CBC 解前 1023 字节，其余 XOR appid 倒数第二字符）。

| | 一键解析 (wx86dbed6ac1691c08) | 解析去水印助手 (wx028a103c6b3c6119) |
|---|---|---|
| 后端 | `https://app.cuntujun.com/api/v2` | `https://yy.yyymvp.com/` |
| 解析端点 | POST `/media/detail {link, code, appId}` | GET `/query?url=&token=&id=&user_id=` |
| 鉴权 | code = wx.login 一次性凭证（jscode2session 严校验，40407） | token = wx.login 换发，服务端绑定微信身份 |
| 图片去水印 | 服务端代理解析后下发干净 URL | 同左；`api_url_image` 代理（s20217250.tuanyougou.com/api/image.php?url=）**已 404 失效**，且仅作直连失败后的兜底 |

**结论**：两者均为"服务端代理解析"模式——去水印发生在其服务器上（下发干净 URL 或转存图），
端点与微信身份强绑定，**无法脱离微信复用**；且转存图会被重编码（用户观察到"保存的图片不是原图"即此原因）。
本 App 的本地方案（微博 woriginal>orj1080>large、小红书 sns-bak 备份域、抖音 playwm→play）直接取平台原始档，
画质优于小程序方案，无需也不应接入它们的后端。

注意：wx028a103c 的壳子是拼多多商城模板改造（hutaojie 品牌），解析页面混在 chunk 中——解包后按
`grep 水印|解析|query|xiazai` 定位业务代码，勿被壳子页面列表误导。

### 抖音图集新版分享路径 slides（2026-11-06 实测）

v.douyin.com 短链对图集作品会 302 到 `/share/slides/{id}/?...&is_slides=1&schema_type=37`。
- `slides` 页是**客户端渲染壳**（26KB，无 `window._ROUTER_DATA`）→ SSR 路线拿不到数据
- 同一 id 改用 `/share/note/{id}/` 请求即有完整 SSR（`loaderData["note_(id)/page"].videoInfoRes.item_list`）
- 图集 item：`aweme_type=2`，`images[]` 每项只含 `uri/url_list/download_url_list/width/height`；
  背景音乐被塞在 `video.play_addr`（值是一个 mp3）
- live 图（实况）的 `live_photo/live_image` 字段在 share SSR 里可能缺失，需 WebView 捕获补


### 微博作者水印：URL 无解，必须图像处理（2026-11-06 实测）

用真实带水印样本（weibo.com/7820903416/5362205998713188）逐档下载目检：

| 档位 | 尺寸 | 体积 | 水印 |
|---|---|---|---|
| large / original | 2316x3088 | 1.42MB | **有**（中部「微博 @重生小羊无敌版」）|
| mw2000 | 2000x2667 | 1.15MB | 有（同一水印）|
| woriginal | 2316x3088 | 0.63MB | 有（同一水印）|
| orj1080 | 1080x1440 | 0.23MB | 有（同一水印）|

→ 水印在上传时烧入源图，所有 CDN 档位都带，换前缀/参数无效；
   平台只在作者开启"图片水印"时添加（居中 或 右下角）。
→ 同类小程序的"去水印"同样是图像处理，只是在**服务端**做后转存
   （解析去水印助手的 api_url_image 代理 https://s20217250.tuanyougou.com/api/image.php?url=
    就是这个角色，现已 404），这也解释了"保存的不是原图"。

本 App 方案（on-device，画质更好）：iOS Vision 文字识别定位水印行
（含 @/微博/weibo、位置在中部带或底部、行高≤6%图高），只修补框内笔画像素；
Vision 未命中时回退到"像素行带限定修补"。

### 小红书图片：H5 版带水印，原图在图片 CDN（2026-11-06 实测）

笔记页 `imageList[]` 里给的 `urlDefault`/`url` 都是 **H5 带水印版**：
`http://sns-webpic-qc.xhscdn.com/{日期}/{hash}/notes_pre_post/{fileId}!h5_1080jpg`
→ 1080×1080、约 400KB、**正中压制「小红书」水印**（该后缀是签名的一部分，
去后缀/换后缀一律 403）。

同一 fileId 在图片 CDN 上可直取原始上传文件：

| URL | 结果 |
|---|---|
| `https://sns-img-hw.xhscdn.com/notes_pre_post/{fileId}?imageView2/2/w/0/format/jpg` | 2160×2160 / 1.15MB / **无水印** |
| `https://sns-img-hw.xhscdn.com/notes_pre_post/{fileId}` | 2160×2160 HEIC / 1.85MB / **无水印** |

因此解析器按 fileId 直接拼原图地址，候选链：
`hw(jpg) → bd(jpg) → 原始 H5 地址`。避免用 HEIC（文件名按 .jpg 会 UTI 不符）。
